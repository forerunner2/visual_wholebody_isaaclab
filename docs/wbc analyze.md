# 四足-机械臂全身运控项目

> 需要的基础：了解RL运控，做过基础的locomotion、manipulation任务。
---

## 原理

1. 该任务面对感知-抓取任务，采用的技术路线是：**分层控制 + 策略蒸馏**。
2. 低层（走 + 末端跟踪）练好后**冻结**，成为高层的"运动原语"。
3. 高层先让一个**状态教师**用 RL 在"全状态 + 物品特权特征"里学会抓取，再用 **DAgger** 把这个行为**蒸馏**进一个只看相机（+ 本体状态）的**视觉学生**。
4. 本质：**用 RL 解决"怎么做"（在干净的特权状态里探索），用监督模仿解决"怎么看"（把已经知道答案的行为，映射到可部署观测上）。**

---

## 1. 感知-抓取任务的分析

为什么不直接使用端到端（视觉感知->动作）的方法进行控制（即现在VLA/WAM的技术路线）呢？这是因为，"视觉输入->动作"的方案等于让策略**同时**解两个难题：

- 一个**控制/探索**问题："这么多步该输出什么动作才能把物体拿起来？"
- 一个**感知**问题："这几帧像素里，物体在哪、朝向如何、我的手和它什么关系？"

两个难题耦合在一起，credit assignment（功劳归谁）横跨感知和控制两层同时传播：走慢一点、没认对物体、IK 没够到……全都搅进同一个梯度里。结果就是样本效率极差、训练非平稳、而且**像素恰恰是 sim2real 里最不可靠的信号**。

Teacher–student 的解决办法非常朴素：**把这两件事拆开**。

> 控制问题 → 交给 RL，但给它一个**净化过的特权状态**（物体位姿、关节、目标全给你），让它专心探索"该怎么做"。
> 感知问题 → 交给监督学习，去拟合一个**已经知道答案的老师**。

这样，RL 不需要从像素里"悟"，学生不需要靠奖励去"探索"。两者各自只做自己擅长的一半。

## 2. 总体架构

整条管线是**两个控制层、三张网络**：低层一张（冻结的"运动原语"），高层两张——**教师**（特权视角）和**学生**（可部署视角），两者输出**同一个 9 维动作空间**。它们**自下而上训练、逐层冻结**。

### 2.1 一张表看全（各网络的角色与 I/O）

| 层 | 频率 | 网络 / 算法 | 输入（观测） | 输出 | 状态 |
|---|---|---|---|---|---|
| 低层 | 50 Hz | RSL-RL PPO | 训练含特权 744 = 66 + 特权18 + 历史660；部署 726 = 66 + 历史660 | 18 = 腿12 + 臂6（臂走 IK 置 0） | ✅ 冻结 |
| 高层·教师 | 6.25 Hz | SKRL PPO `[512,512,256]` | 1094 = 物品特征1024 + 状态61 + 动作历史9 | 9 维语义原语 | 训练期；练完冻成"标签器" |
| 高层·学生 | 6.25 Hz | DAgger + GRU | 62269 = 相机12×54×96 + 本体61 | 9 维语义原语（与教师同空间） | 最终部署 |

> **9 维语义原语 = 速度命令(2) + 末端 EE 目标(6) + 夹爪开合(1)**。教师和学生输出的是**同一个 9 维空间** —— 这正是 `MSE(学生, 教师)` 能做逐维回归的前提。

### 2.2 分层与接口（核心数据流图）

```
                高层 6.25 Hz
   ┌──────────────────────────────┬──────────────────────────────┐
   │  教师 SKRL-PPO（特权）         │  学生 GRU-MLP（可部署）        │
   │  obs 1094 = 特征1024          │  obs 62269 = 相机12×54×96     │
   │            + 状态61 + 历史9    │               + 本体61        │
   │       ↓ 动作9                 │  ── DAgger 打标签(MSE) ─→ 动作9│
   └──────────────────────────────┴──────────────────────────────┘
                                  │  9 维语义原语
                                  │  （速度2 + EE目标6 + 夹爪1）
   ┌──────────────────────────────▼──────────────────────────────┐
   │   低层 50 Hz（冻结）          obs 726 = 66 + 66×10 帧历史      │
   │   RSL-RL PPO → 12 维腿动作；臂走 DLS IK，夹爪走位置目标         │
   └──────────────────────────────┬──────────────────────────────┘
                                  │  腿力矩 + 臂/夹爪位置目标
   ┌──────────────────────────────▼──────────────────────────────┐
   │   物理 200 Hz：B1+Z1 四足 + 桌面 + 可抓物体                     │
   └─────────────────────────────────────────────────────────────┘
```

### 2.3 关键澄清：冻结的低层住在「环境」里，不在高层网络里

上面的低层框，对高层来说**不是另一个要加载的网络**，而是**环境内部一个已经配好的控制器**——和 DLS IK、PD 力矩、物理引擎平级。高层从"输出 9 维"到"拿到观测/奖励"，中间的低层推理、IK、力矩、物理对它全是黑盒：

```
高层策略（独立网络，只认 9 维语义原语）
   │ 输出 9 维
   ▼
┌─ 环境（MDP 黑盒）──────────────────────────────────────────────┐
│  9 维 → 拆成 速度命令(2) + EE目标(6) + 夹爪(1)                  │
│    ▼ 每 4 个物理子步（= 50 Hz）                                  │
│  拼 726 维低层观测 → 冻结低层网络 → 12 维腿动作                    │
│    ▼                                                           │
│  腿 PD 力矩 + 臂 DLS IK + 夹爪位置目标 → 推进 200 Hz 物理          │
└────────────────────────────────────────────────────────────────┘
   │ 返回：观测 + 奖励（教师）；学生只用自己的观测（靠 MSE，不靠奖励）
   ▼
高层策略
```

### 2.4 训练顺序（自下而上）

```
① 低层  ── PPO（RL，含动力学特权）──▶ 冻结成「运动原语」
        （只练：走稳 + 把末端送到随机目标）
② 教师  ── PPO（RL，全状态 + 特征）──▶ 冻成「答案生成器 / 标签器」
        （只练：在特权世界里学会"该怎么抓"）
③ 学生  ── DAgger（监督，MSE）──▶ 最终部署
        （只练：用相机 + 本体，复现教师给出的 9 维动作）
```

**关键点**：冻结低层 = 把"会走、能把末端送到位"压缩成一个 **9 维语义原语**。于是高层不面对 18 个关节，只面对"往哪走 / 手去哪 / 夹爪开合"，带来三个结构性好处：

1. **动作语义化**：高层在说"朝物体平移 2cm"，而不是调 6 个电机——后者对物体任务毫无意义。
2. **信用解耦（最值钱）**：低层"腿怎么站稳"已经被单独解决、单独验收过；高层学抓取时，腿的失败不再污染臂的学习信号。否则"腿没站好→掉了→负奖励"会一路追责到臂策略，谁也学不好。
3. **稳定、奖励稠密的基座**：低层把"摔到地上"压得很低，高层大部分时间都存活在"任务进行中"的状态里。

注意：**低层自己内部还藏着一次 teacher–student**（训练期用特权动力学参数编码器 `priv_encoder`，部署期换成只吃历史观测的 `history_encoder`）。所以整条管线 = **"冻结 + 两次蒸馏"**，同一个思想在两层各出现一次（详见 §6）。

## 3. 高层教师

教师是训练期专用的**状态策略**（SKRL PPO，`[512,512,256]`）。它学的东西就一句话：

> **输入 1094 维观测 → 输出 9 维语义原语**，且这个输出要能（在冻结低层的配合下）把物体抓起来。

### 3.1 输入 / 输出，精确到每一维

**输入（观测）1094 = 1024 + 61 + 9**：

| 段 | 内容 | 性质 |
|---|---|---|
| 0–1023 | 物品"抓取描述子"特征 | 特权（学生看不到） |
| 1024–1084 | 机器/物体状态 61 维：物体位姿 6 + 末端位姿 6 + 关节 19 + 关节速度 18 + 速度命令 3 + **当前 EE 目标 6** + 基座速度 3 | 特权 + 本体 |
| 1085–1093 | 动作历史 9（最近几步自己输出了什么） | 本体 |

**输出（动作）9 维**：

| 维 | 含义 | 去向 |
|---|---|---|
| 0–2 | EE 目标**位置增量** | 累加进 EE 目标 → IK |
| 3–5 | EE 目标**朝向增量** | 累加进 EE 目标 → IK |
| 6 | 夹爪 开(≥0) / 合(<0) | 夹爪位置目标 |
| 7 | 前向速度 | 写进 `commands` → 低层网络 |
| 8 | 转向速度 | 写进 `commands` → 低层网络 |

### 3.2 关键：0–6 是"输出"，不是"喂给它的"

最容易绕晕的一点。要分清三样东西：

| | 是什么 | 谁产生 |
|---|---|---|
| 观测 1094 | 输入 | 环境测出来 |
| **EE 目标 6 维** | 环境里的**持久状态** | 教师每步**累加**出来，被 IK 去追 |
| 动作 9 维 | 输出 | 教师**网络一次前向** |

所以 **0–6（EE 目标 + 夹爪）是教师网络的输出**，和 7–8 是**同一次前向**算出来的，**没有分开的公式**。它"依据什么算"？正是观测里的**特权信息**（1024 特征 + 物体位姿）+ **本体信息**（末端位姿、关节、当前 EE 目标、命令、基座速度）+ **动作历史**。RL 用奖励告诉它"这种观测下 0–6 这么给是对的"。

注意：观测的 61 维里**已经含有一个"当前 EE 目标"(6 维)**，而动作的 0–5 是它的**增量**——两个不是一回事。

### 3.3 EE 目标为什么用"增量"而不是"绝对值"

教师每步输出**增量**（位置 ⊂ ±0.02m、朝向 ⊂ ±0.06rad，裁剪后累加），而不是一次报出绝对目标位姿（`_pre_physics_step`）：

- **限速 + 平滑**：目标一点点挪，IK 追起来不抖；
- **闭环**：每步都能在观测里看到"当前目标被我推到哪了"，形成"逼近物体"的闭环；
- 于是 EE 目标是一个**跨多步的持久状态**：观测看它、动作改它、IK 追它。

### 3.4 一次决策步的完整生命周期

高层 **6.25 Hz**：每 0.16s 决策一次 = **32 个 200Hz 物理子步**（`200÷4=50Hz` 低层，`200÷32=6.25Hz` 高层）：

```
① 教师观察 obs(1094) ─▶ 教师网络 ─▶ 输出 9 维动作
② 环境翻译：EE 目标增量累加 → 新 EE 目标；夹爪；速度写进 commands
③ 环境跑 8 个低层子步（各 50Hz）：
     拼 726 低层观测 → 冻结低层 → 12 腿动作(PD) + 臂走 IK 追 EE 目标 + 夹爪位目标
     （每个低层子步 = 4 个物理子步，8 × 4 = 32）
④ 回传 obs(1094) + reward + done ─▶ PPO 记一条样本
```

**一个高决策步只产生一条 (obs, action, reward) 样本**；步内 8 次低层推理对 PPO 是透明的、不产生样本。

### 3.5 9 维原语怎么变成"真正的控制"（三路拆开）

9 维**不是整块塞给低层网络**，而是环境拆成三路（`_apply_action` / `_compute_low_level_observations`）：

```
教师动作 9 维
   ├─ 0~5 EE 目标增量 → 累加 EE 目标 ─────────▶ DLS IK（臂，直接追目标，不经低层网络）
   ├─ 6   夹爪 ───────────────────────────────▶ 夹爪位置目标（直接给）
   └─ 7~8 速度 → commands（进低层观测726）────▶ 冻结低层网络 → 12 维腿 PD 力矩
```

关键细节：低层网络输出的 6 维臂动作被**直接置 0**（`_apply_action`），**臂只由 IK 驱动**；低层网络真正负责的是**腿**。

### 3.6 训练与课程

- **算法**：PPO（skrl）。并行 N 个环境，rollouts=16；GAE 算 advantage；policy/value 都是 `[512,512,256]`；KL 自适应 LR(0.008)、RunningStandardScaler 归一化观测、梯度裁剪 1.0。
- **奖励**：进度式"靠近(0.5) → 抬升(1.0) → 抓起(3.5)" + 塑形（末端朝向对齐 0.01、底座朝向 0.25、底座接近 0.01、抓取高度 0.5、底座高度 0.55、动作平滑 −0.001 等）。
- **课程**（`common_step_counter` 驱动）：

| 步数 | 开启 | 效果 |
|---|---|---|
| 0 | 物体放手边 | 只练"伸手-抓-抬"近端操作 |
| >15000 | 动作延迟 1 步 | 更接近真实部署 |
| >20000 | 抓起 = 抓稳 25 步 | 从"碰到"升级到"拿住" |
| >30000 | 开指令奖励 / 惩罚 / 站立抓 | 关注"接近后别乱跑、站好再抓" |
| >45000 | 重采样更远目标 | 逼它带底座走位去抓 |

> 一句话：**教师是"答案生成器"，不是最终产物**——它在无噪的特权世界里用 RL 摸清"该怎么抓"，把这些（状态 → 动作）答案留给后面的 DAgger 当标签。

## 4. 高层学生

学生学的是：**相机（深度图 + 语义分割(也就是类别标签)）+ 本体感知 → 9 维语义原语**，用 `MSE(学生, 教师)` 逐维对齐教师——**纯监督回归，没有 value / critic / 环境奖励**。

### 4.1 观测怎么来：62269 = 图像 62208 + 本体尾 61

**图像**（`pick_multi_vision_env.py`）：

- 两台 TiledCamera（前视 + 腕部），各输出深度图 + 语义分割图；
- 物体在 USD 里打 `"graspable"` 语义标签 → `_target_mask` 压成二值 mask（`seg != 0`）；
- 深度 `_normalize_depth`：clip 0–2m、近场(<0.15m)置 0、÷2 归一到 [0,1]；
- 每台相机 2 通道（mask + masked_depth），两台共 4 通道 × 3 帧历史 = **12 × 54 × 96 = 62208**（相机 `img_delay_frame=4` 模拟真实传输延迟）。

**本体尾 61 维**（**不含物体位姿**——这是关键，见 4.3）：

```
末端位姿6 + 关节19 + 关节速度18 + 速度命令3 + 当前EE目标6 + 动作历史9 = 61
```

### 4.2 网络结构（`scripts/dagger/train_student.py` 的 `Policy`）

```
图像 12×54×96 ─▶ CNN(DepthOnlyFCBackbone54x96) ─▶ 64 维 depth_feature ─┐
本体尾 61 ─────────────────────────────────────────────────────── cat ─┤
                                                                    ▼
                                                           125 维 (61+64)
                                                                    │
                                                    GRU(hidden=128)  ← 时序上下文，episode 结束重置
                                                                    │
                                                    MLP ─▶ 9 维动作
```

- CNN：`Conv(12→32) → MaxPool → ELU → Conv(32→64) → Flatten → Linear → 64`；
- GRU 记序列上下文（速度/意图/相机滞后这些单帧看不到的量），`terminated` 时隐状态置 0。

### 4.3 为什么不端到端、为什么留本体信息

学生**不是纯像素端到端**，本体信息是故意留的：**难而廉价可得的信息（自身运动学）本来就该留着，不该让网络再学一遍**——部署时关节编码器、本体命令都是白给的。真正被藏起来、逼学生用视觉补的，只有**物品的语义位置/姿态**。

> 通识：**藏掉"关于环境的难感知量"，保留"关于自己的确定量"。**


### 4.4 怎么学：DAgger 监督 MSE

- 学生**自己开环境**（on-policy），教师给每个访问到的状态输出 9 维标签；
- 损失 = `MSE(学生9维, 教师9维)`：动作是连续语义量，MSE 是"高斯噪声假设下的最大似然"；
- 冷启动前约 4000 步教师代开；`replaced_action` 把安全约束写进标签。

**关键反直觉点**：学生**不"理解"这 9 维的含义**，只是被训练成"这种输入下，输出和教师一样的那 9 个数"。9 维进环境后走**和教师完全相同的翻译链 + 同一个冻结低层**。

## 5. DAgger：这门方法里唯一真正的"算法"，也是本文最核心的干货

### 5.1 为什么纯行为克隆（BC）会死

BC = 收集一串专家的 (状态, 动作)，监督回归。它的死法是 **covariate shift（协变量漂移 / 复合误差）**：

> 学生只在**专家走过的轨迹**上练过。可学生自己有误差——它一旦走偏一点点，就进入一个**专家从未到达过、因而也从未被标注过**的状态区域。在那个区域里，学生没有正确的参照，于是越做越错，误差逐步放大，最终漂移到彻底失败。

一句话：**BC 在"专家分布"上拟合得很好，但学生其实会访问"非专家分布"，那部分一片空白。**

### 5.2 DAgger 的闭环：让训练分布追上"学生自己的分布"

DAgger（Dataset Aggregation）用两条规则堵上这个洞：

1. **让学生上驾驶位。** 环境由**学生自己**驱动（而教师只在旁边看），于是收集到的状态是学生**真实会访问**的状态，而不是理想轨迹；
2. **教师对每个学生访问到的状态补打标签。** 于是那些"走偏了"的状态也有了正确答案。

效果：训练数据分布从"专家分布"被逐步拉向"学生自己会走的分布"，空白区被填上，漂移被闭环纠正。

本实现还加了一个**冷启动**细节：开头一小段（约 4000 步）先让**教师**开环境（`teacher_pretrain`），保证初始数据是干净的专家轨迹、覆盖成功示范；之后才切到学生自己开、教师只打标签。这避免了"学生什么都不懂就上驾驶位，把数据分布一开始就带崩"。

### 5.3 两个体现"工程智慧"的细节

**细节一：标签不一定是教师原话。** 环境里有一个安全覆盖 `replaced_action`：当机器人已经太靠近物体时，环境会把"继续前进"这条速度命令**强制置 0**（安全约束）。DAgger 用的标签是**替换后的安全动作**，不是教师的原始越界动作。这是把**安全约束直接写进监督目标**——学生学到的就是"靠近就减速/停"的**安全版专家**，而不是事后靠负奖励慢慢磨。

**细节二：可选辅助头。** 可以让学生多输出一个"我是不是快抓到了"的预测（`pred_success`），作为一个辅助回归目标，迫使学生内部形成"成功近在眼前"的隐式表征。

## 6. 贯穿全篇的暗线：不对称信息（asymmetry）

把前面散落的几点串成**一条原则**，你就能把整条管线看成一个东西：

> **训练时，允许策略"看到"比部署时更多的信息；训练末，把这份多余信息蒸馏掉。**

在这条管线上它出现了**三次**：

| 层次 | 训练期特权 | 部署期观测 | 蒸馏手段 |
|---|---|---|---|
| 低层 | 动力学参数（质量/摩擦/电机强度）→ `priv_encoder` | 只靠观测历史 → `history_encoder` | 隐性蒸馏（DAgger 内循环里训 history encoder 去拟合 priv 隐变量） |
| 高层教师→学生 | 全状态 + 物品 1024 维特征 | 相机 + 本体状态 | DAgger（动作标签回归） |
| （你熟悉的 AMP） | 参考动作数据集（训练期参考） | 只有策略自己 | 判别器（对抗地匹配参考分布） |

**洞察**：特权信息的价值在于**降低探索难度**——RL 在特权世界里更容易"想清楚"；蒸馏的价值在于**把它翻译到可部署信号**。教师–学生、priv→history、AMP，本质都是"**同一个行为，从好观测搬到差观测**"的三个实现。
